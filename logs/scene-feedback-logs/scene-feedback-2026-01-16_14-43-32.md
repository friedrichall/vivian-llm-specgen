## 3) Functional Requirements (Player-Facing)

### FR-1: Lever / Handle operation
**User can click/drag (or click-to-toggle) the toaster handle** (`toaster3/Handle`) to start a toast cycle.

- **When handle is pushed down**:
  - Toaster enters **Toasting** state.
  - LED turns **on** (visual emissive/color change).
  - Heating elements optionally shift to a “heated” look (color change or emission).
  - Toasting lasts for a duration derived from knob setting (see FR-3).
- **When cycle completes**:
  - Handle returns to up position (animated).
  - Toast pops up (animated) if toast is present/assigned.
  - LED turns off (or goes to idle indicator depending on design).

### FR-2: Stop button
**User can press Stop** (`toaster3/StopButton`) to immediately cancel toasting.

- Cancels active cycle, returns handle to up.
- Heating/LED visuals stop.
- If toast is in-progress, it does **not** “progress” further.

### FR-3: Rotary knob sets toast level/time
**User can rotate knob** (`toaster3/RotaryButton`) to select a toast level.

- The knob has a visible marker: `RotaryButtonMarker`, which must rotate with the knob and serve as the indicator.
- Rotation clamps to a defined min/max angle.
- Selected value affects:
  - Toasting duration and/or browning level.
- No numeric labels are present in the model; UI feedback may be via:
  - subtle tick sound,
  - optional floating UI text near toaster,
  - or just knob position.

### FR-4: Function button (snowflake) toggles “Defrost”
**User can press FunctionButton** (`toaster3/FunctionButton`) to toggle **Defrost mode**.

- Defrost mode modifies toast cycle:
  - increases total time or adds a preheat stage.
- Visual feedback:
  - FunctionButton changes material state (e.g., brightness) and/or LED blink pattern.

### FR-5: LED indicator behavior
`toaster3/LED` acts as an indicator:
- **Off** when idle.
- **On** (or emissive) when toasting.
- Optional: **Blink** when defrost enabled or when done.

### FR-6: Toast presence & popping (using existing toast meshes)
The scene contains three toast groups (`Toast1`, `Toast2`, `Toast3`) each made of:
- Bread mesh + Crumb mesh overlay.

Required behavior:
- Toast should be considered the “bread to toast” for the cycle.
- On completion: toast(s) animate upward (“pop”) relative to toaster.

**Note:** Currently toast objects are not positioned inside toaster in the images. Implementation must therefore define either:
- (A) reposition toast objects at runtime into toaster slots, or  
- (B) spawn/clone toast into slots and keep the originals as props.

## 4) Interaction Design (Inputs)

### 4.1 Supported input methods
- Mouse:
  - Click on buttons to press.
  - Click-drag handle down/up (or click toggle).
  - Click-drag knob to rotate (or click steps).
- Optional touch parity (tap/drag) if needed.

### 4.2 Interaction hit targets
Because meshes currently have no colliders:
- Add colliders to:
  - `Handle`
  - `StopButton`
  - `FunctionButton`
  - `RotaryButton`
- Recommendation: **BoxCollider** or **MeshCollider (convex)** depending on accuracy/perf needs.

---

## 5) State Machine

### 5.1 Primary states
- **Idle**
  - Handle up
  - LED off
  - Heating off
- **Armed** (optional intermediate)
  - Handle down but preheating not started (if you want a short delay)
- **Toasting**
  - Timer running
  - LED on
  - Heating on
- **Done**
  - Toast pops
  - LED off or blink briefly
  - Returns to Idle
- **Cancelled**
  - Triggered by Stop
  - Returns to Idle quickly

### 5.2 Mode flags
- **DefrostEnabled** (toggled by FunctionButton)
- **ToastLevel** (set by RotaryButton)

## 6) Animations / Transform Behaviors (No new measurements)

### 6.1 Handle animation (`toaster3/Handle`)
- Animate local position along the handle’s functional axis (down/up).
- Use existing transform orientation: Handle is rotated ~ -90° around X (quaternion ~ -0.707, 0,0,0.707), so choose a consistent **local axis** for travel (implementation-defined, validated in-editor).
- Should not detach from body visually.

### 6.2 Button press animation (`StopButton`, `FunctionButton`)
- Small local translation inward along their local normal.
- Return on release.

### 6.3 Knob rotation (`RotaryButton`)
- Rotate around its local forward axis.
- Ensure `RotaryButtonMarker` child rotates with parent (already parented correctly).

### 6.4 Toast pop animation (`Toast1/Toast2/Toast3`)
- Move toast group(s) upward relative to toaster.
- Because toast objects are currently separate in world space, define a **toast-slot anchor** approach:
  - Create empty transforms under `toaster3` at runtime or in prefab:
    - `SlotLeft`, `SlotRight` (and optional `SlotCenter`)
  - During toasting: toast positioned at “down” anchor
  - On done: toast moves to “up” anchor

## 7) Toast “Browning” Visual Progression
The toast uses:
- Bread texture (`bread`) + crumb overlay (`ToastCrumb`, brown).

Implement browning without changing geometry:
- Increase opacity/strength of `ToastCrumb` material over time, or
- Lerp crumb color darker, or
- Swap textures/material variants (light/medium/dark).

Must work for each toast set:
- `Toast1/Bread1` + `Toast1/Crumb1`
- `Toast2/Bread2` + `Toast2/Crumb2`
- `Toast3/Bread3` + `Toast3/Crumb3`
